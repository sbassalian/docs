---
title: "Get publish status"
openapi: "GET /meta_ads/publish_status"
---

A light poll for the ads you just created. Unknown ids and ads from other organizations are left out of the response.

Step 4 of the [Meta ads automation flow](/essentials/meta-ads-automation).

## States

| `state` | Meaning | What to do |
| --- | --- | --- |
| `queued` | Waiting to publish | Wait |
| `publishing` | Publishing to Meta | Wait |
| `published` | On Meta, paused | [Launch](/api-reference/endpoint/meta-ads/launch-ad) when ready |
| `active` | On Meta and turned on | Nothing |
| `failed` | A publish step failed. `error_message` and `last_step` say where. | Fix the cause and [retry](/api-reference/endpoint/meta-ads/retry-ad) |

`status` is Meta's delivery status (`ACTIVE`, `PAUSED`, `DELETED`, `ARCHIVED`), separate from `state`.

Each call counts toward your hourly limit, so poll every few minutes with all your ids in one call, not once per ad.

## Authentication

Any organization API key works, including view-only keys. A key acts as the person who created it, so that person needs the owner, admin or viewer role. See [Rate limits and authentication](/api-reference/introduction).

## Errors

| Status | When |
| ------ | ---- |
| `401` | Missing or invalid API key, or the person who created the key is no longer an owner, admin or viewer of the organization |
| `404` | organization_id is not a child brand of the key's organization |
| `429` | Rate limited: 2 seconds between requests, plus the hourly cap |

<RequestExample>

```bash cURL

     -H "Authorization: Bearer YOUR_API_KEY"
```
