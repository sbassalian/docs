---
title: "Retry an ad"
openapi: "POST /meta_ads/{id}/retry"
---

Queues a failed ad to publish again. Each publish step skips what already exists on Meta, so the retry resumes where the last attempt stopped. An ad that failed while launching is launched again after it publishes.

Retry is only for ads with `state: failed`. Look at `error_message` first: some failures, such as a video that is still processing on Meta or a partnership permission that has not reached Meta yet, clear up on their own, while others (an expired Meta connection, a missing permission) need you to fix something before a retry can work.

## Authentication

Needs a **full-access** API key whose creator is an owner or admin. View-only keys, and keys whose creator has the viewer role, get `403`. See [Rate limits and authentication](/api-reference/introduction).

## Errors

| Status | When |
| ------ | ---- |
| `401` | Missing or invalid API key, or the person who created the key is no longer an owner, admin or viewer of the organization |
| `403` | View-only API key, or the key's user is not an owner or admin |
| `404` | organization_id is not a child brand of the key's organization |
| `422` | The ad is not in the failed state, or no ad with this id in your organization |
| `429` | Rate limited: 2 seconds between requests, plus the hourly cap |

<RequestExample>

```bash cURL
curl -X POST "https://api.growi.io/api/public/v1/meta_ads/101/retry" \
     -H "Authorization: Bearer YOUR_API_KEY" \
     -H "Content-Type: application/json" \
     -d '{
       "launch_after_publish": true
     }'
```

</RequestExample>

<ResponseExample>

```json 202
{
  "success": true,
  "data": {
    "meta_ad_id": 9013,
    "state": "queued",
    "retrying": true,
    "queued": true
  }
}
```

</ResponseExample>
