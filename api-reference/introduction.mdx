The Growi API lets your systems do what the dashboard does: record sales from your
own checkout, manage the creators in your campaigns, and read content, sales and
payout numbers for reporting.

```bash Base URL
https://api.growi.io/api/public/v1
```

## Your first request

Create a key under **Settings → Developer → API keys**, then list your brands:

```bash
curl https://api.growi.io/api/public/v1/organizations/brands \
  -H "Authorization: Bearer growi-sk-YOUR-API-KEY"
```

## The basics

| Topic | In short |
| --- | --- |
| [Authentication and keys](/api-reference/authentication) | Send `Authorization: Bearer <key>`. A **full** key reads and writes. A **viewer** key is read-only (`GET` only), so it's safe to share with a BI tool or agency. |
| [Rate limits](/api-reference/rate-limits) | 40 requests per hour per key, and at least **2 seconds** between calls. `X-RateLimit-*` headers show where you are; a `429` comes with `Retry-After`. |
| [Child brands](/api-reference/child-brands) | A key belongs to your top-level organization. Pass `organization_id` to read one of its child brands. |
| [Dates, money and errors](/api-reference/conventions) | New endpoints take and return ISO 8601 dates (`YYYY-MM-DD`, UTC days). Errors are JSON with an `error` message. |
| [Changelog and deprecations](/api-reference/changelog) | What changed, and which endpoints are deprecated. Deprecated endpoints keep working and send `Deprecation`, `Link` and, once a removal date is set, `Sunset` headers. |
