<Info>
  **Prerequisite** You need an admin or owner role in your Growi organization and a full-access API key.
</Info>

## Overview

If your store doesn't run on Shopify, creators can still request free samples in Growi. Instead of Growi placing a Shopify order, Growi sends each request to you with the creator, the product and the shipping address, and you create the order in your own system.

You can receive requests in two ways:

- **Webhooks**: Growi POSTs a `sample_request.*` event to your webhook URL as soon as something happens.
- **API**: you list sample requests, approve or reject them, and report shipments.

Most brands use both: webhooks to react right away and the API to approve requests and send tracking back.

## How it works

1. You choose which products creators can request in your campaign.
2. A creator in the campaign opens the **Sample Request** tab, picks a product and confirms their shipping address.
3. Growi sends `sample_request.created`.
4. The request is approved, either automatically (when the campaign auto-approves samples) or by you through the API. Growi sends `sample_request.approved`.
5. You create the order on your side and ship it.
6. You report the shipment (order number and tracking link) through the API. Growi sends `sample_request.shipped`.

<Tip>
  Create the order when you receive `sample_request.approved`, not `sample_request.created`. A created request may still be rejected.
</Tip>

## Set up

<Steps>
  <Step title="Get an API key">
    In the Growi dashboard, open **Settings → Developer → API keys** and create a full-access key. Read-only keys can list requests but can't approve or update them.
  </Step>
  <Step title="Add your webhook URL">
    Open **Settings → Webhooks** and add an HTTPS URL. Every active URL receives every event, including the [campaign creator events](/essentials/campaign-creator-webhooks).
  </Step>
  <Step title="Choose sample products">
    Open your campaign, go to **Advanced options → Offer free samples**, and select the products and variants creators can request. Your Growi catalog includes the products synced from your connected channels, such as TikTok Shop or Amazon. Turn on **Auto approve** if every request should be approved right away.
  </Step>
</Steps>

## Webhook events

| Event | Sent when |
| --- | --- |
| `sample_request.created` | A creator requested a sample |
| `sample_request.approved` | The request was approved and is ready to ship |
| `sample_request.rejected` | The request was rejected |
| `sample_request.shipped` | The request was marked as shipped |
| `sample_request.delivered` | The request was marked as delivered |
| `sample_request.cancelled` | The request was cancelled |

Delivery works like the other Growi webhooks: an HTTPS `POST` with a JSON body, signed with `Authorization: Bearer <your newest growi-sk API key>`, retried up to 3 times on a non-2xx response. Delivery is at-least-once, so deduplicate on `idempotency_key`.

`sample_request` always reflects the request as it is when the event is delivered, so a `sample_request.created` event can already show `"status": "approved"` when the campaign auto-approves.

## Statuses

| Status | Meaning |
| --- | --- |
| `pending` | Waiting for your approval |
| `approved` | Approved, ready to ship |
| `shipped` | You reported a shipment |
| `delivered` | You reported a delivery |
| `rejected` | You rejected the request |
| `cancelled` | Cancelled for another reason |

## Use the API

All examples use the base URL `https://api.growi.io/api/public/v1`.

### List pending requests

```bash
curl "https://api.growi.io/api/public/v1/sample_requests?status=pending" \
  -H "Authorization: Bearer YOUR_PUBLIC_API_KEY"
```

To poll for changes, pass `updated_since` with the time of your last sync:

```bash
curl "https://api.growi.io/api/public/v1/sample_requests?updated_since=2026-10-21T00:00:00Z" \
  -H "Authorization: Bearer YOUR_PUBLIC_API_KEY"
```

### Approve or reject

```bash
curl -X POST "https://api.growi.io/api/public/v1/sample_requests/812345/approve" \
  -H "Authorization: Bearer YOUR_PUBLIC_API_KEY"

curl -X POST "https://api.growi.io/api/public/v1/sample_requests/812345/reject" \
  -H "Authorization: Bearer YOUR_PUBLIC_API_KEY"
```

When the sample was picked as part of the creator's campaign application, approving the sample also accepts the application, and rejecting it also rejects the application. This matches what happens on Shopify stores.

### Report the shipment

```bash
curl -X PATCH "https://api.growi.io/api/public/v1/sample_requests/812345" \
  -H "Authorization: Bearer YOUR_PUBLIC_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "status": "shipped",
    "order_id": "FB-100231",
    "order_name": "#100231",
    "tracking_url": "https://www.ups.com/track?tracknum=1Z999AA10123456784"
  }'
```

Send `"status": "delivered"` once the package arrives. You can also send `order_id`, `order_name` or `tracking_url` without a `status` to update them on their own.

## Limits

- API requests count toward your hourly limit, with at least 2 seconds between requests. Use webhooks to avoid polling often.
- Requests are listed for your organization's campaigns and your child brands' campaigns.
- Only samples fulfilled by you appear here. Samples on Shopify stores are still sent as Shopify orders, and TikTok Shop samples stay in TikTok Shop.
